# Academic document design and formatting

Standalone Academy capability inspired by document-design best practices. Not dependent on the Toolkit Document Architect plugin or specific DOCX libraries.

## Authority first
Use the actual university module handbook, assessment template, institutional style guide or journal instructions. Document styling is not evidence of meeting a rubric. A general convention (e.g. A4, readable type, reasonable margins) may be offered as a **proposed default**, never falsely attributed to the university. Citation style/spacing rules depend on current authority.

## Structural design
- Use real document heading styles with meaningful hierarchy and navigable reading order.
- Check cover/title page only if required, sections, bibliography, appendices, footnotes, section breaks, automatic numbering and appropriate page numbering.
- Use accessible contrast, alt text for informative graphics, descriptive link text and header rows in data tables; avoid layout tables that impair screen readers.
- Ensure captions identify what a figure/table contains; preserve source credit and permissions.
- Control table width, header repetition, widow/orphan control, cross-reference stability and content overflow.
- Keep text and citations semantically unchanged while formatting. Significant textual changes are separate edits, requiring approval.

## Production and proof
When a tool to create/edit the intended document format exists, create the actual DOCX/Google Doc/PDF. For DOCX/PDF, render real pages and inspect title/first, densely formatted, widest table, references and last page; repeat after fixes. Validate the file structure and accessibility with available validators. A page preview or Markdown output alone doesn't establish an artifact exists.

When **file creation is unavailable**, provide a proposed style specification, template instructions or copy-ready content and explicitly mark artifact production NOT_VERIFIED; do not invent file links.

When **creation succeeds but rendering is unavailable**, retain the genuine created file if the user permits an unverified draft, but label visual layout and accessibility `NOT_VERIFIED` and never call it submission-ready. If the requested output requires verified visual quality, withhold any `PASS` certification and explain the missing renderer. A structurally valid document is not a visually inspected document. Never invent sandbox URLs or claim accessibility certification without a run.

## Required completion wording

If no DOCX was created, state **Artifact creation: NOT_VERIFIED**. If the DOCX exists but was not visually rendered and inspected, state **Visual layout: NOT_VERIFIED**; do not imply it was checked merely because the filename exists. An explanatory sentence without the explicit missing-check status is insufficient for formal Academy submission readiness.
